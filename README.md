# Telecom Antifraud

Работающий прототип кейса Nexign «Антифрод без прослушки»: риск вызова и номера, точные вклады признаков, граф NetworkX и защищённый процесс регистрации общественно важных организаций.

**Стек:** Python 3.11+, scikit-learn, NetworkX, FastAPI. Для локального состояния используется SQLite. Обязательная стратегия и дополнение к ТЗ: [docs/strategy_ru.md](docs/strategy_ru.md).

**Ни один вызов не блокируется.** `review` — рекомендация проверки. Экстренный вызов обходит модель и БД. Организация подаёт заявку; подтверждает её только администратор после проверки номера и операторских атрибутов. Простого совпадения Caller ID недостаточно.

## Быстрый запуск в Windows и VS Code

Откройте папку проекта в VS Code. Команды выполняются из корня проекта в PowerShell. Нужен CPython 3.11 или новее.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m antifraud.demo
```

Если окружение `.venv` уже подготовлено, первые две команды не нужны. Демонстрация не подключается к телефонной сети и сохраняет ответы в `artifacts/demo_results.json`. Файл `.vscode/settings.json` указывает на интерпретатор проекта; при необходимости выберите его командой VS Code Python Select Interpreter. В конфигурации запуска есть API и автономная демонстрация.

## API и пример оценки номера

Создайте три разных ключа в текущем PowerShell и запустите сервер. Команды не записывают секреты в репозиторий.

```powershell
$env:ANTIFRAUD_OPERATOR_KEY = & .\.venv\Scripts\python.exe -c 'import secrets; print(secrets.token_urlsafe(32))'
$env:ANTIFRAUD_ADMIN_KEY = & .\.venv\Scripts\python.exe -c 'import secrets; print(secrets.token_urlsafe(32))'
$organizationKey = & .\.venv\Scripts\python.exe -c 'import secrets; print(secrets.token_urlsafe(32))'
$env:ANTIFRAUD_ORG_KEYS_JSON = @{demo_hospital=$organizationKey} | ConvertTo-Json -Compress
.\.venv\Scripts\python.exe -m antifraud.seed_demo
# Сохраните нужный ключ из переменной для поля x-api-key в Swagger.
# Например, $env:ANTIFRAUD_OPERATOR_KEY выводит операторский ключ в вашем терминале.
.\.venv\Scripts\python.exe -m uvicorn antifraud.api:create_app --factory --host 127.0.0.1 --port 8000
```

Swagger доступен по адресу [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), состояние — [/health](http://127.0.0.1:8000/health). В поле `x-api-key` указывается ключ требуемой роли. Отсутствующий ключ не заменяется общим демонстрационным паролем.

В `runtime/demo_requests.json` есть готовые тела запросов для `/v1/calls/score`: личный звонок, массовый обзвон, веер, больница, малозаметное мошенничество и вызов 103. Для оценки номера отправьте на `/v1/numbers/score` объект с `number`, равным `caller` из примера, и `at`, равным `started_at` из того же примера. Это обеспечивает согласованность момента оценки и загруженной истории.

Для демонстрации заявки возьмите номер больницы из `runtime/demo_requests.json`, подайте `number` и `justification` на `/v1/privileges/requests` с ключом организации. Затем администратор подтверждает заявку через `/v1/admin/privileges/{id}/approve`, указав проверенные `verified_subscriber_id`, `verified_operator`, `verified_trunk`, `evidence_reference` и будущую дату `expires_at`. Для проверки защищённого звонка его `started_at` должен быть позже подтверждения, а `caller_identity_verified` — `true` от доверенного источника оператора. В реальной системе эти поля не выбирает звонящий.

Сценарий `antifraud.demo` автоматически выполняет весь процесс, включая подмену номера и отзыв. `scripts/run-demo.ps1` — сокращённый запуск уже установленного проекта с заполнением демоистории и сервером на localhost.

## Контракты API

| Метод и маршрут | Назначение | Доступ |
| --- | --- | --- |
| `GET /health` | Состояние и наличие модели | Без ключа |
| `POST /v1/history` | Загрузить 1–1000 завершённых CDR | Оператор |
| `POST /v1/calls/score` | Оценить вызов на момент начала | Оператор |
| `POST /v1/numbers/score` | Оценить текущее поведение номера | Оператор |
| `POST /v1/privileges/requests` | Подать заявку на привилегию | Организация |
| `GET /v1/privileges/requests` | Просмотреть собственные заявки | Организация |
| `GET /v1/admin/privileges` | Просмотреть реестр заявок | Администратор |
| `POST /v1/admin/privileges/{id}/approve` | Подтвердить после проверки | Администратор |
| `POST /v1/admin/privileges/{id}/revoke` | Отозвать привилегию | Администратор |
| `GET /v1/admin/audit` | Последние 100 событий аудита | Администратор |

`risk_score` — индекс 0–100, `factors` — все вклады в логарифм отношения шансов. `null` означает отсутствие оценки, а не нулевой риск. `review_threshold` хранится в шкале 0–1; сравнение идёт до округления. При повторной загрузке одинаковый `call_id` не дублируется; другая запись с тем же ID даёт 409 и откат всей пачки.

Поля аудио, расшифровок и произвольные поля отклоняются. Авторизация удостоверяет интеграцию оператора; она не доказывает подлинность телефонной сигнализации сама по себе. Нельзя предоставлять операторский ключ организациям или вызывающему абоненту.

## Данные и воспроизводимость

```powershell
.\.venv\Scripts\python.exe -m antifraud.generate --seed 42
.\.venv\Scripts\python.exe -m antifraud.train
.\.venv\Scripts\python.exe -m antifraud.demo
.\.venv\Scripts\python.exe -m pytest -q
```

Эти команды пересоздают только генерируемые файлы данных и модели в `data/` и `artifacts/`. Генератор не использует внешние источники и реальные телефонные номера. Файл `requirements.lock.txt` фиксирует проверенные версии зависимостей; обучение выполнено в Python 3.12.14.

| Файл | Содержимое |
| --- | --- |
| `data/calls.jsonl` | 155 967 сырых завершённых вызовов; поля `group_id`, `split`, `call` |
| `data/queries.jsonl` | 1 400 запросов оценки на заданный момент |
| `data/labels.jsonl` | Метка и сценарий отдельно от модельных признаков |
| `data/features.jsonl` | Снимки признаков для обучения и оценки |
| `data/manifest.json` | Seed, размеры и разбиение выборок |
| `data/policy_cases.json` | Матрица ожидаемого поведения в критических ситуациях |
| `artifacts/model.json` | Проверяемые параметры модели без pickle |
| `artifacts/metrics.json` | Метрики и разрезы по сценариям |
| `artifacts/predictions.jsonl` | Оценки и ожидаемые метки всех примеров |
| `artifacts/demo_results.json` | Полные объяснения и результаты защитных сценариев |

Обёртка `group_id` в сырых файлах служит для воспроизводимости и группового разделения. В API истории передаётся содержимое поля `call`, без `group_id` и `split`. Для тестирования API удобнее `seed_demo`, который создаёт свежие примеры. Исторический набор для обучения не загружается автоматически в онлайн-БД.

## Проверенные результаты и ограничения

На отложенной синтетике: 4 ложные тревоги из 268 легитимных примеров, FPR 1,49%, полнота 92,42%. Цель FPR 1% на тесте **не достигнута**. Порог выбран только на валидации; качество на реальном или закрытом наборе не измерено. Все результаты и дальнейшие шаги приведены в стратегии.

Это локальный прототип без сетевой блокировки, промышленного SLA и интеграции с коммутатором. Экстренный маршрут должен иметь независимый обход на операторском шлюзе, в том числе при отказе всего процесса API. SQLite и пересчёт графа за сутки подходят для демонстрации; под реальную нагрузку потребуются инкрементальные агрегаты и отдельные нагрузочные испытания. У подключённых библиотек FastAPI/Starlette тестовый клиент выдаёт предупреждение о будущем переходе с httpx на httpx2; тесты текущего зафиксированного окружения проходят.
