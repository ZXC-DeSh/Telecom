# Телеком Антифрод

Локальное демо антифрода по метаданным: оценка звонков и номеров, понятные факторы риска и реестр общественно важных организаций. Интерфейс работает на том же FastAPI, что и API, без отдельной сборки фронтенда.

**Стек:** Python, scikit-learn, NetworkX, FastAPI. Интерфейс — обычные HTML, CSS и JavaScript. Состояние хранится локально в SQLite. Все комментарии и строки документации собственного кода — на русском.

## Запуск

Откройте терминал в папке Telecom и выполните:

```powershell
.\.venv\Scripts\python.exe -m uvicorn antifraud.api:create_app --factory --host 127.0.0.1 --port 8000 --reload
```

- [Визуальный интерфейс](http://127.0.0.1:8000/)
- [Документация API](http://127.0.0.1:8000/docs)

Ключи, пароли, роли и переменные окружения не нужны. История готовых примеров появляется автоматически при открытии страницы. Также можно запустить `scripts/run-demo.ps1`.

Если окружения ещё нет:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

## Что можно попробовать

На странице оценки выберите один из восьми сценариев: массовый обзвон, согласованный веер, обычный абонент, звонок больницы, международный звонок, малозаметный обзвон, вызов скорой помощи или подмена номера больницы.

Карточка покажет балл 0–100, порог рекомендации проверки, исторические показатели и полосы вкладов факторов. По кнопке «Все факторы» раскрываются все 15 признаков, включая понижающие риск. Вклады указаны в логарифме отношения шансов — это не прибавки к баллу. Балл вычисляется настоящей моделью, а не задан картинкой или названием сценария.

В поле «Проверить свой номер» можно ввести номер или тестовый ID из готового примера. Если истории нет, интерфейс сообщит об этом без выдуманного нулевого риска. Номер не проверяется по внешним базам. Кнопка «Скопировать ID номера» переносит реальный идентификатор синтетического примера в буфер.

Во вкладке «Привилегированные номера» можно добавить организацию и отозвать привилегию. Добавление сразу привязывает номер к последнему подтверждённому источнику в истории. Согласование, отдельный административный кабинет и управление доступом для демо убраны. Совпадение Caller ID без совпадения абонента, оператора и транка всё равно не даёт привилегию.

**Автоблокировка отключена.** `review` означает рекомендацию проверки без прерывания связи. Экстренные направления защищены независимо от риска номера и доступности модели. Подробное обоснование: [стратегия и дополнение к ТЗ](docs/strategy_ru.md).

## API

Все методы работают без заголовков авторизации.

| Метод | Назначение |
| --- | --- |
| `GET /` | Визуальный интерфейс |
| `GET /health` | Состояние модели |
| `GET /v1/demo/scenarios` | Готовые примеры с загруженной историей |
| `GET /v1/demo/metrics` | Метрики на синтетической выборке |
| `POST /v1/calls/score` | Оценка вызова на момент начала |
| `POST /v1/numbers/score` | Оценка номера по истории |
| `POST /v1/history` | Загрузка до 1000 завершённых вызовов за запрос |
| `GET /v1/privileges` | Реестр привилегий |
| `POST /v1/privileges` | Добавление номера и организации |
| `DELETE /v1/privileges/{id}` | Отзыв привилегии |

Для оценки номера нужны `number` и `at` с часовым поясом. Для добавления в реестр — `number` и `organization`. Схемы запросов и готовые формы доступны в Swagger. Старые маршруты административных ролей и аудита удалены.

## Проверка и воспроизводимость

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m antifraud.demo
# Пересоздание синтетических данных и обучение
.\.venv\Scripts\python.exe -m antifraud.generate --seed 42
.\.venv\Scripts\python.exe -m antifraud.train
```

В `data/` находятся 155 967 завершённых вызовов, 1400 запросов оценки, отдельная разметка и снимки признаков. Номера имеют недозваниваемый префикс `test:`. Разделение по абонентам и времени: 600 примеров обучения, 400 валидации и 400 теста. `artifacts/model.json` содержит параметры модели, `artifacts/metrics.json` — результаты, `artifacts/demo_results.json` — примеры объяснений.

На отложенной синтетике: FPR 1,49%, полнота 92,42%. Цель FPR 1% на тесте не достигнута. Это демонстрационная оценка; качество на реальных данных не измерено. Сами вызовы приложение не маршрутизирует.
