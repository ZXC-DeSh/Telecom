# Антифрод без прослушки

Система выявления потенциально мошеннических телефонных вызовов по метаданным CDR. Проект разработан в рамках хакатона Nexign «Телеком будущего», кейс «Антифрод».

**Демо:** [https://fraud-egg.onthewifi.com](https://fraud-egg.onthewifi.com)  

## Назначение

Решение помогает оператору находить подозрительные звонки и группы номеров без прослушивания разговоров, аудиозаписей и транскрипций. Анализируются только метаданные вызовов: тип, время, длительность, номера участников, IMSI и сведения о переадресации.

Система формирует оценку риска и предоставляет оператору информацию для дальнейшей проверки. Результат скоринга — сигнал для принятия решения, а не автоматический приговор: высокий риск сам по себе не должен приводить к автоматической блокировке вызова.

Решение ориентировано на выявление сценариев S1–S7 из кейса: Wangiri, массовый обзвон, SIM-box, клон SIM/смена IMSI, цепочки переадресаций, карусель и вишинг со спуфингом. При оценке также важно учитывать легитимные сценарии, похожие на фрод: колл-центры, банковские оповещения, диспетчерские, горячие линии и массовые оповещения.

> **Ограничение:** модель обучена на синтетических данных. Полученные на них результаты не гарантируют аналогичного качества на реальном трафике оператора.

## Архитектура

```text
Пользователь / оператор
          |
          v
Frontend (HTML, CSS, JavaScript; Nginx)
          |
          v
Backend (Python, FastAPI, Pydantic)
          |
          +------> CatBoost — оценка риска
          |
          +------> NetworkX — признаки связей между номерами
          |
          v
PostgreSQL — CDR, справочники и результаты анализа
```

### Компоненты

- **Frontend** — веб-интерфейс для просмотра сводки, вызовов, профилей абонентов и подозрительных событий.
- **FastAPI** — HTTP API, валидация входных данных и запуск операций анализа.
- **CatBoost** — классификация вызовов и оценка вероятности фрода на основе подготовленных признаков.
- **NetworkX** — анализ связей между номерами и извлечение графовых признаков.
- **PostgreSQL** — хранение записей CDR и справочника операторских префиксов.
- **Docker Compose** — сборка и запуск backend и frontend как отдельных сервисов.
- **Nginx** — раздача frontend и приём HTTP/HTTPS-трафика. В конфигурации Compose предусмотрено подключение сертификатов из `/etc/letsencrypt`.

В текущей конфигурации `docker-compose.yaml` база данных не описана отдельным контейнером: backend подключается к PostgreSQL, доступному с хоста или по адресу, заданному в конфигурации.

## Функциональность API

В проекте предусмотрены следующие группы операций (доступность конкретного маршрута зависит от текущей версии backend):

| Назначение | Метод и маршрут |
|---|---|
| Проверка состояния сервиса | `GET /health` |
| Сводная статистика | `GET /dashboard/summary` |
| Информация о модели | `GET /model/info` |
| Список вызовов | `GET /calls` |
| Карточка вызова | `GET /calls/{call_id}` |
| Скоринг вызова или набора вызовов | `POST /predict` |
| Запуск анализа CDR за период | `POST /analysis/run` |
| Статус фонового анализа | `GET /analysis/{job_id}` |
| Текущий результат анализа | `GET /analysis/current` |
| Профиль абонента | `GET /subscribers/{msisdn}` |
| Список подозрительных событий | `GET /fraud-alerts` |

Интерактивная документация OpenAPI/Swagger доступна по адресу `/docs`, если маршрут backend проброшен через reverse proxy. Для развёрнутого экземпляра проверьте: [https://fraud-egg.onthewifi.com/docs](https://fraud-egg.onthewifi.com/docs). Если ссылка возвращает 404 или страницу frontend, откройте `/docs` на внутреннем адресе backend, указанном в конфигурации развёртывания.

## Настройка окружения

Backend читает переменные из `Backend/.env`. Создайте этот файл на основе конфигурации, используемой в проекте, и заполните параметры подключения к PostgreSQL и остальные обязательные параметры backend.

Пример принципа настройки:

```dotenv
APP_NAME=AntiFraude API
APP_ENV=local
LOG_LEVEL=INFO
DB_HOST=localhost
DB_PORT=5432
DB_NAME=antifraude
DB_USER=postgres
DB_PASSWORD=postgres
DB_CONNECT_TIMEOUT=3
CORS_ORIGINS=http://127.0.0.1:5500,http://localhost:5500

MODEL_PATH=models/FraudScrope_r9.2.cbm
MODEL_PASSPORT_PATH=models/FraudScrope_r9.2.json
```

Это пример, а не гарантированный полный список переменных: сверяйтесь с настройками подключения в backend. Не коммитьте реальные пароли, токены и другие секреты. Если backend запускается в контейнере, `DB_HOST` должен указывать на адрес PostgreSQL, доступный именно из контейнера, а не на `127.0.0.1` внутри контейнера.

## Запуск через Docker Compose

1. Клонируйте репозиторий и перейдите в его каталог:

   ```bash
   git clone https://github.com/Shshdevs/Antifraud_AIEgg.git
   cd Antifraud_AIEgg
   ```

2. Создайте `Backend/.env` и укажите параметры доступной базы PostgreSQL.

3. Убедитесь, что PostgreSQL запущен, база и схема созданы, а указанные учётные данные имеют необходимые права.

4. Соберите и запустите сервисы:

   ```bash
   docker compose up --build -d
   ```

5. Проверьте состояние контейнеров и журналы:

   ```bash
   docker compose ps
   docker compose logs -f backend
   docker compose logs -f frontend
   ```

6. Откройте `http://localhost` либо порт, заданный через `FRONTEND_PORT`. При наличии настроенных сертификатов и соответствующей конфигурации Nginx HTTPS доступен через `https://localhost` или заданный `FRONTEND_HTTPS_PORT`.

Остановка сервисов без удаления данных:

```bash
docker compose down
```

## Локальный запуск без Docker

Точные команды запуска зависят от файлов зависимостей и точки входа, находящихся в текущей версии репозитория.

1. Установите Python и создайте виртуальное окружение:

   ```bash
   cd Backend
   python -m venv .venv
   ```

   Linux/macOS:

   ```bash
   source .venv/bin/activate
   ```

   Windows PowerShell:

   ```powershell
   .venv\Scripts\Activate.ps1
   ```

2. Установите зависимости из файла зависимостей, присутствующего в `Backend` (например, `requirements.txt`, если он есть):

   ```bash
   pip install -r requirements.txt
   ```

3. Создайте `Backend/.env`, настройте подключение к PostgreSQL и запустите приложение через фактический ASGI-модуль проекта. Типовой пример для FastAPI:

   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

4. Если frontend не раздаётся backend, запустите его согласно конфигурации `Frontend`. Для статического HTML/CSS/JavaScript может быть достаточно Nginx; если проект использует сборщик, следуйте скриптам в `Frontend/package.json`.

## Данные и ограничения

Основная запись CDR содержит:

- `call_type`: `01` — входящий, `02` — исходящий, `03` — переадресация;
- `imsi_a` — идентификатор SIM/абонента A;
- `msisdn_a`, `msisdn_b` — номера участников вызова;
- `call_time` — дата и время вызова;
- `duration_seconds` — длительность в секундах;
- `msisdn_c` — дополнительный номер при переадресации.

Система не анализирует содержимое разговора. Качество результата зависит от полноты CDR, корректности подготовки признаков и репрезентативности данных для обучения. Модель следует оценивать не только по полноте обнаружения фрода, но и по ложным срабатываниям. Решение о блокировке должно приниматься отдельно с учётом цены ошибки и защиты экстренных вызовов.
