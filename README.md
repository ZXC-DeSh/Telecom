# Frontend — Телеком Антифрод

## Возможности

- обзор: сводные показатели, распределение рисков и динамика;
- журнал вызовов: фильтры, пагинация и подробности записи;
- подозрительные события: фильтры и постраничный просмотр;
- профиль абонента: статистика, контакты и связанные подозрительные номера;
- запуск анализа за период и просмотр статуса задачи;
- состояние базы данных и модели, метрики модели;
- отображение ошибок API, проверка состояния backend.

## Запуск

### 1. Запустить Backend

Откройте терминал в папке `Backend` и подготовьте окружение по инструкции самого backend. Типовой запуск из папки, где находится `main.py`:

**Windows (PowerShell):**
```powershell
cd Backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# При необходимости заполните .env на основе .env.example
uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

**Linux/macOS:**
```bash
cd Backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# При необходимости заполните .env на основе .env.example
uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Backend использует PostgreSQL. Перед запуском проверьте параметры подключения к БД в `Backend/.env` и доступность самой базы. По умолчанию API prefix — `/api/v1`, поэтому health endpoint ожидается по адресу `http://127.0.0.1:8000/api/v1/health`.

### 2. Разрешить запросы от Frontend (CORS)

Frontend запускается на отдельном локальном порту, поэтому укажите адрес интерфейса в `Backend/.env`, например:

```env
CORS_ORIGINS=http://127.0.0.1:5500,http://localhost:5500
```

Перезапустите Backend после изменения `.env`. Если у вас уже настроен `CORS_ORIGINS`, добавьте эти адреса к существующим значениям, не стирая остальные.

### 3. Запустить Frontend

В новом терминале из корня проекта:

```bash
python -m http.server 5500 --directory Frontend
```

Затем откройте **http://127.0.0.1:5500**.

Не открывайте `index.html` двойным щелчком: используйте локальный HTTP-сервер.

## Настройка адреса API

По умолчанию Frontend обращается к `http://127.0.0.1:8000/api/v1`. Если Backend работает на другом адресе/порту, в `Frontend/app.js` измените константу `API_DEFAULT`. Это статический интерфейс, сборка npm не нужна.

Документация backend: http://127.0.0.1:8000/docs

## Используемые эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| GET | `/health` | Состояние БД и модели |
| GET | `/dashboard/summary` | Данные обзорной панели |
| GET | `/calls` | Список вызовов, фильтры и пагинация |
| GET | `/calls/{call_id}` | Подробности вызова |
| GET | `/fraud-alerts` | Список подозрительных событий |
| GET | `/subscribers/{msisdn}` | Профиль абонента |
| POST | `/analysis/run` | Запуск аналитической задачи |
| GET | `/analysis/{job_id}` | Статус задачи анализа |
| GET | `/model/info` | Информация о модели |

В запросах используется обёртка backend `ApiResponse`: интерфейс извлекает полезную нагрузку из поля `data`.

## Важно

- Frontend не содержит копию backend и не запускает модель самостоятельно.
- Интерфейс не подменяет отсутствующие данные тестовыми значениями.
- Если БД или модель недоступны, интерфейс покажет сообщение от API.
- Запуск анализа отправляет дату и время без часового смещения в формате, ожидаемом схемой backend.
